# AurumOS - Configuration Guide

## 1. Configuration Files Overview

AurumOS uses several configuration files to manage application behavior. All configuration files are located in the application root directory (`C:\AurumOS\`).

| File | Purpose | Format |
|------|---------|--------|
| `config.json` | Runtime configuration | JSON |
| `version.json` | Version manifest and update info | JSON |
| `db_path.txt` | Database file path | Plain text |
| `database/.license_key` | Encrypted license key | Binary (XOR) |
| `database/.subscription_state.json` | Cached subscription state | JSON |
| `database/.setup_complete` | First-run setup flag | Flag file |
| `database/.unlock_nonce` | Unlock key counter | Plain text |
| `sign_config.json.example` | Code-signing template | JSON |

---

## 2. config.json

**Location**: `C:\AurumOS\config.json`

This is the primary runtime configuration file. It controls the application mode, network settings, and API endpoints.

### 2.1 Structure

```json
{
  "mode": "local",
  "server_ip": "",
  "server_port": 58901,
  "api_base_url": "https://aurum-os-admin.vercel.app"
}
```

### 2.2 Fields

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `mode` | string | `"local"` | Application mode |
| `server_ip` | string | `""` | Host PC IP address (client mode only) |
| `server_port` | integer | `58901` | LAN sync server port |
| `api_base_url` | string | Vercel URL | Remote API server base URL |

### 2.3 Mode Options

| Mode | Description |
|------|-------------|
| `"local"` | Standalone single-PC operation. No network sync. |
| `"server"` | Host mode. Runs the LAN sync server on port 58901. |
| `"client"` | Client mode. Connects to a host PC for sync. |

### 2.4 Example Configurations

#### Single PC (Default)
```json
{
  "mode": "local",
  "server_ip": "",
  "server_port": 58901,
  "api_base_url": "https://aurum-os-admin.vercel.app"
}
```

#### Network Host
```json
{
  "mode": "server",
  "server_ip": "",
  "server_port": 58901,
  "api_base_url": "https://aurum-os-admin.vercel.app"
}
```

#### Network Client
```json
{
  "mode": "client",
  "server_ip": "192.168.1.100",
  "server_port": 58901,
  "api_base_url": "https://aurum-os-admin.vercel.app"
}
```

## 3. version.json

**Location**: `C:\AurumOS\version.json`

Used by the auto-updater to check for and apply updates.

### 3.1 Structure

```json
{
  "version": "1.0.2",
  "download_url": "https://github.com/Jenildholakiya/AurumOS/releases/download/v1.0.2/AurumOS.zip",
  "sha256": "abc123def456..."
}
```

### 3.2 Fields

| Key | Type | Description |
|-----|------|-------------|
| `version` | string | Current version (semver: `major.minor.patch`) |
| `download_url` | string | URL to download the update package |
| `sha256` | string | SHA-256 hash of the update file for integrity verification |

## 4. db_path.txt

**Location**: `C:\AurumOS\db_path.txt`

Contains the full filesystem path to the SQLite database file. This allows the database to be stored on a different drive or network location.

### 4.1 Default Content

```
C:\AurumOS\database\aurum_local.db
```

### 4.2 Custom Database Location

To change the database location:
1. Close AurumOS
2. Move `aurum_local.db` to the desired location
3. Edit `db_path.txt` with the new full path
4. Restart AurumOS

**Example**:
```
D:\Backups\AurumOS\aurum_local.db
```

## 5. Database State Files

These files are stored in the `database/` directory and manage application state.

### 5.1 .license_key

**Location**: `C:\AurumOS\database\.license_key`

Contains the XOR-encrypted license key. The encryption key is the machine ID (derived from MAC address).

**Do not edit this file manually.** Use the license activation screen to manage keys.

### 5.2 .subscription_state.json

**Location**: `C:\AurumOS\database\.subscription_state.json`

Cached subscription state for offline use. Updated when the server is reachable.

```json
{
  "plan": "enterprise",
  "features": ["billing", "stock", "reports", "ai_assistant", "lan_sync"],
  "status": "active",
  "expires": "2026-12-31T23:59:59Z",
  "cached_at": "2026-08-30T10:00:00Z"
}
```

### 5.3 .setup_complete

**Location**: `C:\AurumOS\database\.setup_complete`

Flag file indicating the initial setup wizard has been completed. Its presence prevents the setup wizard from running again.

**To re-run setup**: Delete this file and restart AurumOS.

### 5.4 .unlock_nonce

**Location**: `C:\AurumOS\database\.unlock_nonce`

Counter for generating one-time unlock keys. Incremented each time an unlock key is generated.

### 5.5 .sse_cache

**Location**: `C:\AurumOS\database\.sse_cache`

Cached Server-Sent Events from the license server. Used to maintain real-time license status when the SSE connection is temporarily lost.

## 6. Environment Variables

AurumOS does not require environment variables for normal operation. However, the following can be used for development or debugging:

| Variable | Purpose | Default |
|----------|---------|---------|
| `AURUMOS_DEBUG` | Enable debug logging | Not set (disabled) |
| `AURUMOS_DB_PATH` | Override database path | Reads from `db_path.txt` |
| `AURUMOS_API_URL` | Override API base URL | Reads from `config.json` |
| `AURUMOS_LOG_LEVEL` | Set log verbosity (`debug`, `info`, `warn`, `error`) | `info` |

**Usage** (Windows PowerShell):
```powershell
$env:AURUMOS_DEBUG = "1"
.\AurumOS.exe
```

## 7. Database Configuration

### 7.1 SQLite Settings

The database is configured with these PRAGMA settings (set in `db_manager.py`):

```sql
PRAGMA journal_mode = WAL;           -- Write-Ahead Logging for concurrent reads
PRAGMA synchronous = NORMAL;         -- Balanced safety/performance
PRAGMA foreign_keys = ON;            -- Enforce foreign key constraints
PRAGMA cache_size = -64000;          -- 64MB page cache
PRAGMA temp_store = MEMORY;          -- Temp tables in memory
PRAGMA mmap_size = 268435456;        -- 256MB memory-mapped I/O
```

### 7.2 Database Location Priority

1. `AURUMOS_DB_PATH` environment variable
2. `db_path.txt` file content
3. Default: `database/aurum_local.db`

## 8. Network Configuration

### 8.1 Ports

| Port | Protocol | Purpose | Direction |
|------|----------|---------|-----------|
| 58901 | TCP | LAN sync HTTP server | Inbound (host) / Outbound (client) |
| 58902 | UDP | LAN discovery beacon | Broadcast |
| 7272 | TCP | Network mode (Brain/Client) | Inbound (host) / Outbound (client) |

### 8.2 Firewall Rules

To enable LAN sync, add these Windows Firewall rules:

```powershell
# Allow inbound TCP 58901 (sync server)
New-NetFirewallRule -DisplayName "AurumOS Sync" -Direction Inbound -LocalPort 58901 -Protocol TCP -Action Allow

# Allow inbound UDP 58902 (discovery)
New-NetFirewallRule -DisplayName "AurumOS Discovery" -Direction Inbound -LocalPort 58902 -Protocol UDP -Action Allow

# Allow inbound TCP 7272 (network mode)
New-NetFirewallRule -DisplayName "AurumOS Network" -Direction Inbound -LocalPort 7272 -Protocol TCP -Action Allow
```

### 8.3 Discovery Protocol

UDP broadcast messages are sent every **4 seconds** on port 58902:

```json
{
  "device_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "shop_id": "SHOP-XXXXXXXX",
  "hostname": "WORKSTATION-01",
  "version": "1.0.2"
}
```

## 9. Printer Configuration

### 9.1 Settings (via Settings UI)

| Setting | Description | Default |
|---------|-------------|---------|
| `printer_name` | Windows printer name | System default |
| `paper_size` | Paper size (mm) | `58` (thermal) or `A4` |
| `margins` | Print margins (mm) | `{top: 5, bottom: 5, left: 5, right: 5}` |
| `tag_width` | Tag image width (px) | `400` |
| `tag_height` | Tag image height (px) | `300` |

### 9.2 Supported Printers

- Windows-compatible inkjet/laser printers
- Thermal receipt printers (58mm/80mm) via win32print
- Label printers with Windows drivers

## 10. Scale Configuration

### 10.1 Settings (via Settings UI)

| Setting | Description | Default |
|---------|-------------|---------|
| `port` | COM port (e.g., COM3) | Auto-detect |
| `baud_rate` | Serial baud rate | `9600` |
| `data_bits` | Data bits | `8` |
| `stop_bits` | Stop bits | `1` |
| `parity` | Parity check | `none` |

### 10.2 Auto-Detection

The scale widget can auto-detect the COM port and baud rate:
1. Click **Detect Port** in Settings
2. The system scans available COM ports
3. Tests each baud rate (4800, 9600, 19200, 38400)
4. Returns the first port that returns valid weight data

## 11. Security Configuration

### 11.1 Bastion AI Settings

Configured via the `app_config` table in the database:

| Key | Description | Default |
|-----|-------------|---------|
| `bastion_enabled` | Enable/disable Bastion | `"true"` |
| `bastion_db_watchdog_interval` | DB check interval (seconds) | `30` |
| `bastion_session_guard_interval` | Session check interval (seconds) | `60` |
| `bastion_auto_healer_interval` | Auto-heal interval (seconds) | `300` |
| `bastion_alert_email` | Email for security alerts | (none) |
| `bastion_max_backups` | Maximum backup count | `30` |

### 11.2 Lockout Settings

| Setting | Value |
|---------|-------|
| Max failed login attempts | 3 |
| Lockout duration | 5 minutes |
| Lockout counter reset | After successful login |

### 11.3 Session Settings

| Setting | Value |
|---------|-------|
| Session token storage | Windows registry (`HKCU\SOFTWARE\Microsoft\InputMethod\AOS\SessionCache`) |
| Session backup | Temp file |
| Session validation interval | 60 seconds |

## 12. Update Configuration

### 12.1 Auto-Update Settings

| Setting | Value |
|---------|-------|
| Check interval | On startup + every 24 hours |
| Source | GitHub Releases API |
| Staging folder | `_update_staging/` |
| Protected from update | `database/`, `logs/`, `config.json` |

### 12.2 Update Process

1. Compare `version.json` version with GitHub release
2. Download update to `_update_staging/`
3. Apply staged files before imports on next startup
4. Remove staging folder after successful update

## 13. Logging Configuration

### 13.1 Log Files

| File | Location | Purpose |
|------|----------|---------|
| `app.log` | `logs/app.log` | General application logs |
| `sync.log` | `logs/sync.log` | LAN sync operations |
| `bastion.log` | `logs/bastion.log` | Security events |
| `error.log` | `logs/error.log` | Error traces |

### 13.2 Log Rotation

- Maximum file size: **10 MB**
- Retention: **30 days**
- Rotation: Automatic via BASTION Auto Healer
- Old logs compressed and archived

### 13.3 Log Format

```
2026-08-30 09:47:12 [INFO] [main] Application started
2026-08-30 09:47:13 [INFO] [db_manager] Database initialized: aurum_local.db
2026-08-30 09:47:14 [WARN] [bastion] Session token expired, regenerated
2026-08-30 09:47:15 [ERROR] [sync] Connection refused: 192.168.1.100:58901
```

## 14. Backup Configuration

### 14.1 Automatic Backups

| Setting | Value |
|---------|-------|
| Location | `database/backups/` |
| Maximum count | 30 |
| Trigger | Startup + periodic (Auto Healer) |
| Format | Raw SQLite copy |

### 14.2 Manual Backups

Via Settings > Backup:
1. Choose destination folder
2. Click **Backup Now**
3. File saved as `aurum_local_backup_YYYYMMDD_HHMMSS.db`

## 15. Code-Signing Configuration

### 15.1 sign_config.json.example

Template for code-signing the EXE:

```json
{
  "certificate_path": "path/to/certificate.pfx",
  "certificate_password": "your_password",
  "timestamp_server": "http://timestamp.digicert.com",
  "sign_tool_path": "C:/Program Files (x86)/Windows Kits/10/bin/x64/signtool.exe"
}
```

**Do not commit this file with real credentials.** Copy to `sign_config.json` and fill in values locally.
